# Sony Sound Connect 便携版 · Sound Connect Desktop

**版本 v27** · 2026-10-28 · Windows x64 · 免安装 · 静态链接（无需 VC++ 运行库 / MinGW DLL）

一个用 C++17 + Win32/GDI 从零重写的索尼耳机桌面控制台（对标手机端 *Sony Sound Connect 13.3.0*）。
界面规范取自官方 APK 的资源与 dex（配色、字体阶梯、卡片结构、控件语义），协议走官方 MDR V2（RFCOMM 蓝牙串口）。

| `SonySoundConnectUI.exe`（图形界面） | 3,446,932 B | `8E1ED555D3FCE981` |
| `SonySoundConnectTest.exe`（控制台自检 / 真机探针） | 3,217,951 B | `917391F8E1E6B231` |

导入表只有系统 DLL：`KERNEL32 / USER32 / GDI32 / WS2_32 / msvcrt / bthprops.cpl` —— 拷到任意 Windows 10/11 x64 机器双击即可运行。

## 二、快速开始

1. **先跑模拟**（不碰蓝牙）：双击 `SonySoundConnectUI.exe`，默认进入「模拟设备」会话，四个页面全部可点。
2. **连真机**：
   1. 在 Windows「设置 → 蓝牙」里把耳机**配对**；
   2. 打开程序 → 左侧「设备设置」→ 点「扫描本机蓝牙」；
   3. 在列表里点你的耳机 → 自动填入 MAC 与 RFCOMM 通道并连接；
   4. 未配对时程序会先尝试配对（`BluetoothAuthenticateDeviceEx`），失败会给出原因。
3. 若自动填入的通道连不上，把「通道」改成 `1–30` 之间试（**通道是按机型名推测的建议值，本程序不做 SDP 服务发现**）。
4. 自检：`SonySoundConnectTest.exe --test-sim`，正常结束应为 **98 PASS / 0 FAIL**。

## 三、四个页面

| 页面 | 内容 |
|---|---|
| **概览** | 设备主卡（型号、连接状态、电量、协议版本、当前降噪模式）；**情景调节** 4 张卡片（深度专注 / 办公协作 / 街头通勤 / Hi-Fi 鉴赏，一次点击写入「降噪·环境音 + ULT 模式 + EQ 预设」三维组合）；**聆听模式**（点即下发）；均衡器摘要 |
| **声音控制** | 聆听模式分段（ULT WEAR 只有降噪 / 环境音两态）；**环境音等级滑杆 1–20**（仅环境音模式下可调）；关注语音 / Speak-to-Chat；连接状态与「刷新设备状态」 |
| **均衡器** | 五段均衡器（曲线 + 5 个推子 + dB 数值 + 频点 + ± 微调）；Clear Bass（与五段**独立**，不叠加进整条曲线）；「应用均衡器 + ULT」/「从设备同步」 |
| **设备设置** | 机型切换、MAC/通道输入、启动模拟设备 / 连接真实耳机 / 断开 / 重新读取 / 发送关机；**蓝牙设备发现**（模拟扫描 + 本机蓝牙扫描）；该机型已配置功能清单；电量实时回读 |

窗口为**无边框**（自绘标题栏 + DWM 圆角/投影），支持 Windows 拖拽、贴边、最大化、DPI 缩放（96–240 DPI），窄窗自动把左侧栏收成图标栏。

## 五、环境音等级：为什么显示 1–20，以及它怎么下发

这一块踩过三次坑，写清楚以便日后排查：

**1) 两层模型，不能混用。**
官方 App 内部有 `raw level` 与 `slider progress` 两层，`progress = (raw − min) / step`。旧版本直接把 progress 当等级打印，于是出现「本程序显示 0–19、官方 App 显示 1–20」。现在按 raw 区间打印，滑杆本身仍是 progress 语义。

**2) ULT WEAR 对 `0x60`（能力查询）不回包。**
实测发送 `0x60` 后 1200 ms 无任何回包。因此程序**不能**依赖设备下发范围，否则滑杆会被永久禁用。现在的做法：能力查询失败 → 按真机实测的 `1..20 / step 1` 兜底，并在界面上写明「设备未响应 0x60 能力查询；按实机验证的 1–20 生效区间映射」。

**3) 等级字节在帧尾，且必须同时把 `ncValue` 写 1 才生效。**
NCASM 设置帧（7 字节）：

```
68 17 <totalEffect> <settingType> <ncValue> <voice> <level>
```

真机实测（ULT WEAR）：

| 下发 | 设备回包 | 结果 |
|---|---|---|
| `68 17 01 01 00 00 0A` | `69 17 01 01 00 01 14` | **等级被忽略**（`ncValue=0`） |
| `68 17 01 01 01 00 01/05/0A/0F/14` | `69 17 01 01 01 00 01/05/0A/0F/14` | **1/5/10/15/20 全部原样生效** |
| `68 17 01 01 01 01 0F` | `69 17 01 01 01 01 0F` | 关注语音与等级并存 |

**4) 该固件不接受「关闭」态。**
`68 17 00 ...` 各种组合只回 ACK 不改状态（部分组合反而切到环境音）。因此 ULT WEAR 的模式分段只给「降噪 / 环境音」，点「关闭」会立即被拒并提示原因，而不是假装成功。

**5) 切模式不再掉档。**
降噪帧里那一位是**设备自己的降噪等级**（恒 `0x14`），以前会被写回环境音等级，导致"每切一次模式等级变成 1"。现在降噪/关闭帧写独立字段，环境音等级只在环境音模式下参与比较与回读。

## 六、均衡器

- **五段**（400 / 1k / 2.5k / 6.3k / 16k）+ **Clear Bass** 独立字段：`Clear Bass` **不会**把整条曲线整体抬高，它是独立下发维度（界面文案已标注）。
- ULT WEAR 的 ULT 模式与 EQ 预设同处 `0x58` 帧的 `0x03` 子类型，11 字节：
  `58 03 <preset> <ultMode> 06 <clearBass+10> <b0+10> ... <b4+10>`
- 回读：`0x56` GET → `0x57` RET（也接受 `0x59` 通知）。发送 SET 前会先 `drainBufferedFrames()`，避免把设备对上一次 SET 的回包当成这次 GET 的应答（这曾导致"EQ 调了不生效"——界面永远显示上一轮的值）。
- 「从设备同步」= 主动 `0x56` 读一次；连接成功后也会自动同步一次。

## 七、命令行

### 图形界面（`SonySoundConnectUI.exe`）

```
--page=N            打开指定页面（0 概览 / 1 声音控制 / 2 均衡器 / 3 设备设置）
--model=CODE        ULT | XM5 | XM4 | WF-XM5
--ambient=N         环境音模式（0 降噪 / 1 环境音 / 2 关闭），仅影响启动时的界面状态

--preset=N          EQ 预设序号（0 起）
--connect-sim       启动即连模拟设备
```

这些参数原本是为截图取证加的，日常使用不需要。

### 控制台（`SonySoundConnectTest.exe`）

```
--test-sim / --test  跑严格协议与仿真自检套件（98 项）
--sim [--model ...]  有状态模拟模式（无需蓝牙硬件）
--real <MAC> --channel <N> --model <CODE>   连接真实耳机
--scan               列出模拟设备（不访问蓝牙硬件）
--scan-real          枚举本机已配对/已知蓝牙设备（bthprops）
--help
```

## 八、构建

依赖：MinGW-w64 **g++ 8.1.0**（含 `windres`）。静态链接，产物无外部 DLL 依赖。

```
build_sony_ui.cmd
```

脚本四步：① `windres` 编译图标资源 → ② 编译控制台程序 → ③ 跑 `--test-sim` → ④ 编译 GUI（`-mwindows`）。关键参数：

```
-std=c++17 -O2 -Wall -Wextra
-static -static-libgcc -static-libstdc++ -l:libwinpthread.a
-lws2_32 -lgdi32 -luser32 -lbthprops
```

> 脚本第 5 行默认写死 `C:\Users\liuar\Desktop\tools\mingw64\bin\g++.exe`，找不到会回退到 PATH 里的 `g++`；换机器时把它改成 `set "GXX=g++"` 更省事。脚本末尾有 `pause`，批处理调用时请去掉。

## 十、已知限制

| 限制 | 说明 |
|---|---|
| RFCOMM 通道是推测值 | 不实现 SDP 服务发现；通道靠机型名映射 + 用户手改。连不上请改 1–30 |
| ULT WEAR 无「关闭」态 | 固件实测不接受，界面只给降噪/环境音（非 ULT 机型仍可关闭） |
| `0x60` 能力查询无响应 | 1–20 是实测生效区间，不是设备声明的范围 |
| ULT WEAR 的 DSEE / 编码优先 / 佩戴感应 | 命令格式未核实，界面不提供开关，避免发错帧误伤设备 |
| 多点连接 / LE Audio / 自动关机 / 触控分配 / 头部动作 / Battery Care | 资源里有文案但**无 MDR 命令字证据**，按"不猜测协议"原则未实现 |
| 固件更新 / 360RA 配置 / 账号云同步 / 语音包下载 / 流媒体联动 | 必须联网，不在本工具范围内 |
| 1280×720 下的音效调节页 | 仍需滚动（本版本验收尺寸是 1600×900 与默认窗口） |
| 非 ULT 机型真机验证 | 协议路径共享，但未逐款实测 |

## 十一、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `未检测到蓝牙适配器（系统错误码 259）` | 本机蓝牙被关闭、被飞行模式占用或驱动异常；先确认 Windows 蓝牙能正常搜到设备 |
| `连接蓝牙设备失败，错误码: 10064` | 耳机未开机 / 不在范围内 / 已被别的设备占用（如手机） |
| `10050 (WSAENETDOWN)` | 蓝牙适配器不可用（与 259 同源） |
| 连上了但读不到状态 | RFCOMM 通道不对；把通道改成 1–30 逐个试 |
| 滑杆置灰 | 只有「环境音」模式下等级可调；降噪/关闭态按设计置灰 |
| EQ 调完没反应 | 先点「应用均衡器 + ULT」，或点「从设备同步」核对设备真实值 |
